# 기획서 목업 규칙

목업은 **디자인이 아니라 기획 참고용 와이어프레임**이다. 개발자와 QA가 이 그림을 디자인 시안으로 읽으면 "디자인과 다르다"는 불필요한 문의가 생긴다. 그래서 필요한 정보만 담고 장식은 넣지 않는다.

작업 순서, HTML 작성 방식, PNG 렌더 방법은 평소 하던 대로 한다. 아래는 **그릴 때 지킬 규칙**만 담았다.

## 먼저 확인: CPO BO 작업인가

이 규칙은 CPO BO 기획서용이다. 기획자가 "CPO 요건이야"처럼 직접 말하면 그대로 적용한다. 말하지 않았다면 아래 단서로 판단한다.

- Confluence 스페이스 키가 `CPO`이거나 CPO 기획서 링크를 다루고 있다
- 두레이 요건이나 대화에 CPO BO 화면명(상품전시관리, 주문관리, 매입 현황관리 등)이 나온다
- 이 대화에서 이미 CPO BO 작업을 하고 있다

단서가 다른 프로젝트(예: HMG Board, 멤버십, 그룹웨어)를 가리키면 이 규칙을 적용하지 않고 그 사실을 알린다.
단서가 없어 판단되지 않으면 적용하기 전에 기획자에게 어느 프로젝트인지 한 번 묻는다.

## 1. 색과 형태 (6줄이 전부)

| # | 규칙 |
|---|---|
| 1 | 무채색만 쓴다. 흰 배경, 옅은 회색 선, 회색 채움(라벨 칸, 표 헤더, 검색 패널), 검정 글자 |
| 2 | 강조 버튼은 검정 채움에 흰 글자. 일반 버튼은 회색 채움 또는 흰 바탕에 검정 테두리 |
| 3 | 모서리는 각지게 한다. 예외는 얼럿 상자뿐이다 |
| 4 | 그림자를 쓰지 않는다 |
| 5 | 비활성은 연회색 채움에 중간 회색 글자다. 색을 얕게 쓰는 방침에서도 이것은 남긴다. 그림만 보고 개발하면 틀리기 때문이다 |
| 6 | 글자 위계는 4단이다. 레코드 식별 제목, 화면·섹션 제목·`총 n건`, 라벨, 값·본문. 글꼴은 한 종류 |

색 대신 아래 수단으로 의미를 구분한다.

| 구분할 것 | 수단 |
|---|---|
| 상태(`반려`, `노출중`) | 테두리 있는 작은 알약 뱃지, 상태 텍스트 오른쪽에 인라인 |
| 강조와 일반 액션 | 채움 대비(검정과 회색)와 위치(primary는 항상 맨 오른쪽) |
| 링크 | 밑줄 |
| 현재 페이지 | 굵게와 밑줄 (붉게 칠하지 않는다) |
| 행 구분 | 가로 괘선 하나, 줄무늬(zebra) 금지 |

원천이 `상단 고정은 BG 컬러 변경`처럼 배경색을 문자로 지시했다면 그대로 그린다. 이 규칙이 막는 것은 우리가 임의로 넣는 색이다.

## 2. 캔버스

- 상단 헤더와 좌측 메뉴는 그리지 않는다. 본문 영역(화면 제목 아래)만 그린다.
- 가로 1200~1400px, 가장자리 여백 24~32px을 참고한다.
- 이미지 한 장은 화면 하나다. 여러 장을 세로로 이어 붙이지 않는다. 기획서는 첨부 1개에 이미지 1개다. 얼럿과 부분컷만 한 캔버스에 모아도 된다.
- 동시에 존재할 수 없는 시점(팝업과 그 팝업의 버튼으로 뜨는 얼럿, 입력 전과 후, 조회 성공과 실패)을 한 캔버스에 겹쳐 그리지 않는다. 한쪽만 그린다.
- 기존 화면을 수정하는 일이 대부분이다. 현행 기획서의 해당 UI를 먼저 확인하고 그 구조를 유지한 채 바뀌는 부분만 얹는다.

## 3. 주석은 3종만, 주석인 게 티 나게

| 허용 | 예 |
|---|---|
| 장 이름표 | `목록 화면`, `저장 확인` |
| 트리거 캡션 | `저장 선택 시` |
| 케이스 라벨 | `case1)` |

이 주석은 **화면 테두리 밖 위쪽에 회색 작은 글씨로 한 줄**로 쓴다. 동작이나 조건을 설명하는 문장은 그림에 넣지 않는다. 그것은 description 칸의 몫이다. 화살표, 말풍선, 지시선도 쓰지 않는다. 컨플 UI 칸에 별도 캡션을 달 계획이라면 이미지 안의 장 이름표는 빼서 같은 제목이 두 번 보이지 않게 한다.

## 4. 부품은 라벨의 모양으로 고른다

| 원천 표현 | 부품 |
|---|---|
| 선택지를 나열하고 여러 개 고름(`~상태`, `~유형`) | Checkbox, 전부 펼친다 |
| 선택지를 나열하고 하나만 고름 | Radio, 전부 펼친다 |
| 선택지가 런타임에 조회되는 목록 | Select |
| 자유 문자열(`~명`, `~번호`) | Input |
| 날짜와 기간 | DatePicker, 기간이면 시작과 종료 2개 |
| 여러 줄 입력 | Textarea |
| 읽기 전용 값 | label-value 표의 한 칸 |
| 값이 여러 건 반복 | 표 |
| 값 옆에 조회나 검증 버튼 | Input과 Button |

선택형 조건은 6개여도 드롭다운으로 접지 않고 펼친다. 근거가 없는 부품은 회색 placeholder 박스에 라벨만 적는다.

## 5. 지어내지 않는다

- 원천과 현행 기획서에 없는 필드, 버튼, 문구를 넣지 않는다. 관례상 있을 것 같다는 이유로 `전체` 체크박스나 `[목록으로 이동]`을 넣는 것이 실제 사고 사례다.
- 문구를 모르는 얼럿은 그리지 않는다. 문구를 모르는데 얼럿 존재가 확정된 경우에만 `{문구}`와 `{버튼명}` 빈 골격 1장을 그린다.
- 동작 설명 문장(`승인대기 상태에서만 활성화`)을 화면 안내문으로 옮기지 않는다. 화면에 존재하지 않는 텍스트다.
- 묶어 서술한 항목(`출력: A, B, C`)은 한 칸에 쌓지 않고 컬럼 3개로 나눈다.
- 원천이 비활성 조건(`~인 경우에만 활성화`)을 적었다면 기본 상태를 비활성으로 그린다.
- 아이콘은 얼럿 `✕`, 페이지네이션 화살표, 드롭다운 `▼`만 허용한다.
- 값이 가변이거나 원천이 지정하지 않았다면 `{항목명}` 자리표시자로 쓴다. 건수는 항상 `{n}건`으로 쓴다. 고정 숫자를 쓰면 스펙처럼 읽힌다.
- 목록 표의 행은 같은 값을 반복해 채운다. 상태 컬럼처럼 다양성을 보여야 하는 컬럼만 값을 바꾼다. 서로 다른 필드에 같은 실값을 재사용하지 않는다.
- 두 장 이상에 같은 이름으로 나오는 필드는 이름, 값, 컨트롤 종류, 표 형식을 같게 맞춘다.
- 값이 아닌 영역 전체를 모를 때는 큰 회색 박스로 비우지 않는다. 섹션 헤더, 빈 표 골격, 회색 글씨 `상세: <문서명> 참고` 한 줄을 그린다.

요건에 없는 값을 가정해서 그렸다면, 어떤 값을 가정했는지 그림과 함께 기획자에게 알린다.

## 6. 화면 유형별 골격

### 목록 화면

`[숏컷 밴드] → [검색 패널] → [총 n건 줄] → [표] → [페이지네이션]`

- 숏컷 밴드는 원천에 상태별 건수 숏컷이 있을 때만 그린다.
- 검색 패널은 밝은 회색 바탕에 전폭, 각진 모서리다. 조건 한 줄은 `굵은 라벨(왼쪽 고정폭)`과 `부품들`이다. 기간 검색 행은 항상 맨 마지막, 버튼줄 바로 위다. 버튼줄은 가운데이고 순서는 `초기화`, `검색`이다.
- `총 {n}건` 줄은 왼쪽이다. `엑셀 다운로드`와 `신규 등록`이 그 옆에 붙을 수 있고, 오른쪽 끝은 페이지 크기 드롭다운 하나뿐이다.
- 표는 헤더 행만 회색 채움에 굵게, 가운데 정렬이다. 세로 구분선과 줄무늬는 없다. 상세로 가는 값은 밑줄이다. 컬럼이 많아도 전부 한 장에 넣고, 정지 이미지에는 가로 스크롤이 없으므로 글자를 줄여서라도 다 보이게 한다.
- 행은 기본 5~8행이다. 상태 케이스가 8개를 넘으면 케이스 수만큼 늘린다.
- 페이지네이션은 표 아래 가운데, 현재 페이지만 굵게와 밑줄이다.

### 상세와 등록 화면

`[화면 제목] → [레코드 식별 제목] → 반복{ [섹션 제목] [label-value 표 또는 목록 표] } → [하단 액션줄]`

- 레코드 식별 제목은 원천이 상단 식별 정보를 명시했을 때만 그린다. 상세 화면의 기본이 아니다.
- label-value 표는 4열 격자(`라벨|값|라벨|값`), 라벨 칸은 회색 채움 고정폭, 값 칸은 흰 바탕이다. 세로선과 가로선을 모두 그린다. 목록 표와 반대다.
- 하단 액션줄은 우측 정렬, primary가 마지막이다. `목록으로 이동`은 원천이 언급했을 때만 그린다. 섹션 제목줄에 액션이 붙으면 우측이다.

### 입력 팝업

크기는 캔버스 절반 이상, 흰색에 얇은 회색 테두리, 각진 모서리다. 좌상단 제목은 진회색 타이틀바에 흰 글자, 우상단 `✕`다. 버튼은 하단 가운데 또는 우측에 `닫기`(흰색과 테두리), `적용`(검정 채움) 순이다. 팝업 내부는 원천이 말한 것만 그린다.

### 확인과 경고 얼럿

작게(팝업의 절반 이하), 밝은 회색 채움에 테두리 없음, 모서리는 둥글어도 된다. 제목은 좌상단에 조금 크게 굵게, 본문은 한 줄이다. 버튼은 본문 아래 가운데에 진회색 채움으로 나란히 둔다.

얼럿은 화면 한 장으로 세지 않는다. 같은 화면 안의 상태이므로 부분컷으로 모아 그린다.

### 부분컷

바뀌는 영역까지만 자르고 부모 화면을 통째로 다시 그리지 않는다. 단, 그 안의 표 골격은 전부 그린다. 값을 모르면 값만 비우고 필드 행을 줄이지 않는다. 필드가 3개만 보이면 그 화면에 필드가 3개뿐이라고 읽힌다.

### 엑셀

엑셀 앱 화면은 그리지 않는다. 컬럼 헤더 표를 적고 "엑셀 스크린샷은 직접 첨부 필요"라고 알린다.

## 7. 렌더 후 확인

- 가로로 잘린 곳이 없는가. 표가 넓은데 잘렸다면 글자를 줄이거나 두 장으로 나누고 이유를 알린다.
- 원천에 없는 문구가 들어가지 않았는가. 의심되면 원천과 현행 기획서에서 그 문자열을 검색해 0건이면 지운다.
